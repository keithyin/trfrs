§0读法

串联重复检测有一个共同的困难：你事先不知道要找的东西有多长、从哪里开始、允许多少错误。任何"先假设再验证"的方法都要面对这个循环。TRF 的做法是把循环拆开，让便宜的手段先跑，让昂贵的手段后跑。

因此本书的组织单位不是模块，而是决定。每个决定都写成一张三问卡：

问题

如果不解决，会卡在哪里。问题只用现象描述，不涉及代码。

手段

选择的做法。先给抽象形式，再给参数与边界。

理由

这个手段为什么成立。给论证、给量级、给失效条件。

三问之后才是落点：哪一段代码实现了它，关键变量叫什么。这样读，代码是结论的注脚，不是起点。

§1问题的形状

先把生物学问题翻译成字符串问题。翻译之后，才能谈算法。

1.1 目标输出

输入是一条 DNA 序列 S。字母表是 {A, C, G, T}，另外可能有 N 等未知字符。程序输出一组记录。每条记录有四个核心字段：

字段含义例子
first–last重复区间的起止位置，1 起算，闭区间1--35
period周期，即重复单元的间距7
copies拷贝数，可以有小数5.0
size共识序列长度，通常等于周期7

另有匹配率、空位率、分数、碱基比例、熵和共识模式串。这些字段用于筛选和解释，不参与定位。

1.2 四个未知

称区间 [a, b] 为周期 d 的串联重复，当且仅当：把 [a, b] 切成若干段长为 d 的块，相邻块彼此高度相似。

"高度相似"不能停留在文字上。它必须能算出一个数，并且能和一个门槛比较。本书后面用局部比对分数承担这个角色。

定义里藏着四个未知：

  1. 起点 a。重复可能从任意位置开始。
  2. 终点 b。重复可能在任意位置结束，末端常常不完整。
  3. 周期 d。范围是 1 到 2000。
  4. 容忍度。真实重复有错配和插入缺失，相似不是相等。

四个未知相乘，就是搜索空间。下一节说明它有多大。

1.3 为什么不能直接枚举

最直接的做法是：枚举起点 a 和周期 d，对每一对做一次比对，看分数是否够高。

对数 = n × D （n 个起点，D 个周期）
单次代价 ≈ L × d （L 是比对的长度）
总计 ≈ n × D × L × d

代入一个不算大的例子。取 n = 10⁶（一条细菌基因组），D = 2000，L = 100，d = 100。总计约 2 × 10¹³ 次单元格计算。每次计算要做三次加法和三次比较。这个量级在现代 CPU 上需要数小时到数天。人类基因组的单条染色体是 2.5 × 10⁸ bp，还要再放大 250 倍。

结论很硬：不能对每个位置都做比对。绝大多数位置根本没有重复。必须先有一个廉价手段，把候选缩小到千分之一以下。

1.4 判别标准要满足三条

  1. 可计算。给定区间和周期，能在常数或近常数时间内算出。
  2. 可比较。不同候选之间能排序，能定门槛。
  3. 可解释。门槛有概率含义。否则参数无法迁移到新物种。

这三条要求指向同一个结构：先算分数，再用随机模型给分数定门槛。§2 说明如何把这个结构铺开。

§2四个结构性决定

把问题拆成两级，是整本书的主线。第一级便宜，负责筛。第二级昂贵，负责定。两级之间用一条窄通道连接。通道越窄，总成本越低。

2.1 决定一：先证据，后比对

问题

对每个位置都做比对，成本是 n × D × L。算不完。

手段

用短串精确匹配产生"这里可能有周期 d"的证据。只有拿到证据的距离才进入比对。

理由

真重复几乎必然留下精确的短串匹配。随机序列很少留下长串匹配。短串匹配的次数和 4−k 成正比。

示例

先交代数据。tests/data/small_test.fasta 的第一条记录（>0）长 35 bp，是 7 bp 单元 TCATCGG 首尾相接重复 5 次：

位置 1     7 8     14 15     21 22     28 29     35
     TCATCGG TCATCGG TCATCGG TCATCGG TCATCGG
     └──7──┘ └──7──┘ └──7──┘ └──7──┘ └──7──┘

接下来解释"证据登记"数的是什么。扫描到位置 i 时，程序取以 i 结尾的 4 元组（默认参数下第一档元组尺寸是 4），在历史链表里查找同样的 4 元组上次出现在哪。每找到一个旧位置 j，就记一笔：距离 d = i − j 的户头加一次登记。这条路径是 process_candidate() → add_tuple_match_to_distance_entry()，只记账，不做任何判断。本序列的重复距离 7、14、21、28 都不超过元组尺寸 4 的管辖上限 29，所以每一次登记都来自 4 元组，5 元组和 7 元组在这里一次也没有插手。

登记次数可以手工核对。完整的 4 元组最早结束于位置 4，最晚结束于位置 35。对距离 d，能配上对的两个 4 元组，前一端最早在 4、最晚在 35 − d，所以登记次数 = (35 − d) − 4 + 1 = 32 − d。比如 d = 7：结束于位置 4 的 TCAT 配结束于位置 11 的，结束于位置 5 的 CATC 配结束于位置 12 的……结束于位置 28 的 TCGG 配结束于位置 35 的，恰好 25 对。

再对程序做插桩统计，实测数字与上式完全一致：

距离 d登记次数
手工 = 32 − d		进入比对的次数说明
7251（位置 12）位置 12 时攒够判据，开出第一张矩阵
14181（位置 19）同样只开一张矩阵
21111（位置 27）同样只开一张矩阵

"进入比对"指的是通过全部统计判据、真正启动环绕 DP 的次数，对应 criteria_count[d]。同一距离开过一次矩阵后，其覆盖区间内的后续命中会被 distance_seen 表挡住，不再重复比对，所以每个 d 至多 1 次。58 次登记换 3 张矩阵，约 19 比 1。没有第一级，每个位置、每个周期都要开一张矩阵。放到基因组上，差距就是 1.3 节算出的那笔账。

2.2 决定二：把周期变成距离

问题

周期是待求量。如果把它当未知数，比对就要对每个 d 重做。

手段

不先求周期。先记录"位置 i 与位置 i−d 有相同短串"这个事实。d 就是距离。周期从距离里长出来。

理由

周期是距离的一种。反过来不成立，距离不一定是周期。这个不对称让"记账"成为可能：按 d 建表，只增加计数，不做判断。

示例

还是这条 35 bp 序列。位置 4 的 TCAT 在位置 11、18、25、32 再次出现。程序记下四个距离：7、14、21、28，各立一个户头，不做任何判断。

四本账走向不同。7 的账先攒够，触发比对。14 和 21 的账后攒够，也各触发一次。28 的账始终没攒够，窗口滑过之后清零。周期这个词要到直方图阶段才出现，而且最后写进报告的周期由比对结果决定，不由任何一笔账决定。

这一步把"搜索参数"换成了"索引键"。表按 d 建，共 maxdistance 张。每张表只装落在滑动窗口内的证据。这个结构在 Q2 展开。

2.3 决定三：门槛来自随机模型

问题

证据数量多少算多？门槛不能靠人工试错。

手段

建一个随机序列模型：每个位置以 PM/100 的概率与配对位置相同，以 PI/100 的概率发生插入缺失。用模拟求分位数，存成表。

理由

门槛要有概率含义，才能迁移到新数据。表比分位数公式更容易实现，也更容易复现原程序。

示例

d = 7 的门槛是：等待 18，证据和 5。看一个真候选怎么过线。

  • 位置 11，第一条证据到账：4 个匹配碱基，差 1 个，不过线。
  • 位置 12，相邻命中合并成 5 个碱基，过线。

换成一条随机序列：两个指定位置共享一个 4 元组的概率是 1/256。一次孤立命中只记 4 个碱基，多数直接卡在证据和上。就算偶然凑够，第一条证据也未必落在窗口打开后的 18 个位置之内。两道锁都要过，随机命中很难连续通过。

这两个参数只出现在门槛里，不出现在分数里。这一点在 2.4 说明。

2.4 决定四：报告口径统一

问题

同一段重复会被多个 d 触发。报告的周期、区间、拷贝数可能互相矛盾。

手段

固定一条后处理链：按周期上限裁剪，按起点排序，按规则去冗余，按发现顺序编号。周期取比对直方图的众数，不取候选 d。

理由

候选 d 只是线索。最终周期必须由比对结果决定。重叠记录必须合并，否则输出不可用。

示例

这条 35 bp 序列进入第二级两次：一次以 d = 7，一次以 d = 14。两次都达标，区间都是 1 到 35，分数都是 70。用 -r 关掉去冗余，输出里能看到两条记录。

后处理链把它们合成一条：区间重叠 100%，满足 90%；14 是 7 的整数倍；14 的分数 70 不高于 1.1 × 70。三条都满足，删除周期 14 的记录，保留周期 7。剩下的记录按发现顺序重新编号。

报告字段也有固定来源。period 取直方图众数，size 取共识长度，copies 取回溯计数。三个数来自三条路，后处理保证口径一致。

2.5 打分模型

第二级需要一把尺子。TRF 用局部比对分数。分数由三部分组成：

α = +2 匹配
β = −5 错配
δ = −7 插入或缺失（一个空位）

分数 = α × 匹配数 + β × 错配数 + δ × 空位数

三个数不是随便选的。看比值：

  • 一个错配要用 2.5 个匹配补偿。5 / 2 = 2.5。
  • 一个空位要用 3.5 个匹配补偿。7 / 2 = 3.5。

比值决定容忍度。绝对值为 2、5、7 还是 4、10、14，不影响判定，只影响门槛的换算。这也是为什么默认分数门槛 50 对应"至少 25 个匹配碱基"。

为什么用局部比对

重复的两侧是普通序列。全局比对会把两侧的错配算进分数。分数被侧翼拖低，好重复也会被漏掉。

局部比对给每个单元格加一个下界 0：

S(i, j) = max( 0, S(i−1, j−1) + 相似度, S(i−1, j) + δ, S(i, j−1) + δ )

这个 0 有两个作用。第一，比对可以在任意位置重新开始。第二，负分不会传染。代价是：只有 0 下界还不够，比对会到处重新开始。Q4 用一个"屏障"补上这个漏洞。

为什么 PM 与 PI 不进分数

因为分数的单位是"碱基"，概率的单位是"事件"。两者不能相加。PM 与 PI 只决定用哪张门槛表：

PM元组长度元组最大距离表
804, 5, 729, 159, maxdistanceWAITDATA80 / SUMDATA80
753, 4, 5, 729, 43, 159, maxdistanceWAITDATA75 / SUMDATA75

其他 PM 值没有表。程序直接报错退出，退出码 −13。这是原程序的行为，Rust 版保留。

派生量：maxdistance

候选距离的上限不总等于 MaxPeriod。计算顺序如下：

// src/state.rs
maxdistance = maxperiod;
if maxdistance < 500 { maxdistance = 500 }
maxdistance = min(maxdistance, 0.6 × n)
maxdistance = max(maxdistance, 200)

取 n = 1000、MaxPeriod = 2000：先得 2000，再取 min(2000, 600) = 600，最后得 600。含义是：短序列不搜索超过 0.6 n 的周期。一个周期超过序列长度六成的重复，最多只有一份半拷贝，证据不足。

易错点

MaxPeriod 是报告的周期上限，maxdistance 是搜索的距离上限。两者可能不同。调参时不要混用。

Q1怎样避免对每个周期都做比对

第一级只需要回答一个问题：在这个位置，哪些 d 值得进入第二级。回答必须便宜。比一次比对还贵的筛选没有意义。所以第一级不许做近似匹配，只许做精确匹配。

问题

候选空间是 n × D。逐对做比对算不完。需要一个不比对也能产生线索的手段。

手段

取长度 k 的精确短串，称元组。用哈希表记录它最近出现的位置。新位置与旧位置的距离 d 就是线索。

理由

真重复的相邻副本共享大量元组。随机序列共享元组的概率是 4−k。两个概率差三个数量级以上。

Q1.1 元组与编码

称长度 k 的短串为元组（tuple）。长度 k 的元组有 4k 种。把 A、C、G、T 分别编码为 0、1、2、3。一个元组就是一个 4 进制整数：

code = b1 · 4k−1 + b2 · 4k−2 + … + bk

k = 7 时，码值范围是 0 到 16383。一张 16384 项的整数表就能做"最近位置"索引。这个规模可以放进缓存。

滑动一位时不必重算整个元组。丢掉最高位，补上最低位：

// src/scan.rs:767
code = (code % FOUR_TO_THE[k − 1]) × 4 + index[sequence[i]]

程序只维护 k = 7 的码。短元组是它的后缀。4k 取模就得到末 k 位：

// src/scan.rs:771
tuple_code[3] = code
tuple_code[2] = code % 45
tuple_code[1] = code % 44

一次滚动，三个尺寸同时更新。没有额外成本。

Q1.2 历史链

每个元组码一个入口，指向"最近一次出现"的历史槽。每个历史槽存三个字段：位置、同码的上一次位置、码值。槽放在环形数组里，写满就覆盖最旧的槽。

// 抽象形式
head[code]  →  history[h]  →  history[h.previous]  →  …  →  0

history[h] = { location, previous, code }

在位置 i 得到码 c 之后，程序做三步：

  1. 写入新槽 h，previous 指向原来的 head[c]。
  2. head[c] 改为 h。
  3. 沿 previous 走链。每到一个槽 y，算 d = i − y.location。

走链时有两个截断条件：

  • d > tuple_max_distance[g]：太远。把链在此断开，后面的更远，不必再看。
  • d ≤ tuple_max_distance[g] 但 d ≤ tuple_max_distance[g−1]：这个距离归更短的元组管。跳过，不记账。

这里 g 是元组尺寸的序号，取值 1 到 3，不是元组长度本身。tuple_max_distance[0] = 0，所以序号 1 负责从 1 开始的距离。

元组长度 k负责的距离区间理由

Q1.3 为什么这个手段成立

不漏。设区间是周期 d 的重复。只要某一份副本里有连续 k 个碱基没有错误，这个元组就会在下一份副本的对应位置再次出现。两者相隔 d，程序一定记账。真实重复的错配率通常低于 20%。此时 4 连无错的概率是 0.8⁴ ≈ 0.41。一条几百 bp 的重复几乎不可能一个 4 连都没有。

不滥。设序列是随机的。两个指定位置共享一个元组的概率是 4−k。取 k = 4 得 1/256。取 k = 7 得 1/16384。

证据的期望数量约为：

E[证据数] ≈ n × W × 4−k （W 是链长，即窗口内的位置数）

W 随 d 增长。保持 E 不变，就要让 4−k 同步下降。这就是元组长度分级的原因：距离越大，指纹越长。原程序的 WAITDATA 与 SUMDATA 表在 d = 30 和 d = 160 处出现台阶，正好对应两次切换。

Q1.4 边界与代价

非 ACGT 字符。N 之类的字符不能进入元组。程序遇到它就重置编码，并从下一个好字符开始重建。重建要等累计 7 个好字符才结束，因为滚动码需要完整的 7 位。

// src/scan.rs:737
if i == 0 || !is_acgt(sequence[i]) {
    badcharindex = i; build_entire_code = true;
    // 向前找连续 mintuplesize 个好字符
}

这一步同时解释了另一个现象：跨过 N 的重复会被切成两段。程序不会把 N 两侧的片段接起来。

链长上限。历史槽总数是 2 × tuple_max_distance + 4。超出后旧槽被覆盖。这不会漏掉近处的证据。因为被覆盖的槽位置更旧，距离已经超过上限。

成本。编码是每次一位的常数操作。走链的成本等于链上落在区间内的槽数。区间内证据越密，成本越高。这个成本由数据的重复程度决定，不由 n 单独决定。

Q2距离表会膨胀，怎样控制

Q1 每发现一条线索就写一张表。表按 d 建，最多 2000 张。若不加控制，表会无限增长，遍历也会失控。

问题

每个 d 一张表，条目随时间累积。判断"哪些 d 还值得跟踪"不能靠扫描 2000 个表。

手段

表只保留滑动窗口内的条目。相邻条目合并。活跃的 d 串成双向链表，再加一层 50 间距的标签桶。

理由

证据有时效。太旧的匹配说明重复已经中断。链表把"遍历全部距离"变成"遍历活跃距离"。

Q2.1 窗口：证据的保质期

表项是一个二元组 (location, size)。location 是匹配段的最右位置，size 是这段连续匹配的长度。窗口左端这样算：

// src/scan.rs:138
windowleftend = min(location − d, location − 20) + 1

d ≥ 20 时窗口长度是 d + 1。d < 20 时窗口长度是 21。含义是：至少要覆盖一份完整拷贝，短周期再给 20 个位置的余量。

插入新证据之前，程序从窗口左端丢弃过期条目。丢弃时不能只减条目数，还要减匹配碱基数：

// src/scan.rs:144
nummatches −= entry[lowindex].size;
numentries −= 1;
关键细节

nummatches 数的是匹配碱基，不是命中次数。一次 4 元组命中贡献 4。两个相邻命中合并且只加 1，因为新命中的 4 个碱基里有 3 个已经数过。

这个细节决定了门槛的量纲。判据说"匹配碱基至少 5 个"，不说"至少命中 5 次"。

Q2.2 合并：把连续命中压成一段

// src/scan.rs:157
if numentries != 0 && entry[highindex].location == location − 1 {
    entry[highindex].location += 1;
    entry[highindex].size += 1;
    nummatches += 1;
}

一段 100 bp 的精确匹配会产生 97 个连续命中。合并后只剩 1 个条目，size = 100。条目数从 O(L) 降到 O(1)。这是摊销 O(1) 的来源。

Q2.3 活跃清单：双向链表

只有"非空"的距离才需要参与判据。程序把这些距离串成一条按数值排序的双向链表：linkdown 指向更小的活跃距离，linkup 指向更大的。

判据要在 [lo, hi] 区间内求和。从 d 出发沿 linkdown 走就是降序，沿 linkup 走就是升序。走出区间就停。成本是 O(区间内的活跃距离数)，不是 O(maxdistance)。

新增距离时要把它插进有序链表。若每次都从链表头找位置，插入会退化成 O(D)。程序用一个标签数组做插入游标：

// src/scan.rs:379
top_tag = maxdistance / 50
tag[t] = 第 t 组的插入游标（每 50 个距离一组）

插入 d 时先看 tag[d / 50]。游标比 d 小，就从游标处接上；游标比 d 大，就沿 linkdown 往下找第一个小于 d 的活跃距离。插入后再抬高受影响的游标。

游标把"从链表头扫描"换成"从附近的锚点扫描"。插入的平均成本接近常数。判据的遍历成本不变，仍是活跃距离数。

Q2.4 摘链：不再活跃就退出

// src/scan.rs:248
if distance[d].numentries == 0 {
    从链表摘除 d;
    untag_distance_window(d, linkdown);
    return 1;
}

摘链发生在判据遍历邻居时。遍历到一个距离，先清掉它的过期条目。条目清空就地摘链。摘链保证"死掉的距离"不再产生任何成本。这也是为什么活跃距离数通常只有几十，远小于 2000。

Q2.5 内存代价

表在初始化时一次性分配。每个 d 的容量是 max(d, 20) + 1。总条目数约 maxdistance² / 2。取 maxdistance = 2000 得 200 万条，每条 8 字节，约 16 MB。这是可以接受的固定成本。它也解释了为什么 MaxPeriod 设成 2000 而不是 100000。

Q3什么时候相信证据

证据只说明"这两个位置共享一段短串"。它不说明这里存在重复。随机序列也会产生证据。判定需要一个可计算的显著性判断。

问题

证据数量本身没有尺度。1 条算多还是 100 条算多，取决于 d、窗口长度和随机模型。

手段

三条判据：等待时间、区间证据和、区域竞争。阈值来自模拟表，按 d 查。

理由

真重复有三个特征：证据来得早、总量大、且在邻域内最强。三条判据各抓一个特征。

Q3.1 判据一：等待时间

把当前位置 i 的窗口左端记为 left = max(0, i − max(d, 20))。窗口内的第一段证据必须出现在 left + wait[d] 之前。

first_location ≤ max(0, i − max(d, 20)) + wait[d]
first_location = 最老一段证据的起点 = entry[lowindex].location − size + k

为什么这条判据有效：如果重复真实存在，从窗口打开到第一条证据之间的间隔应当很短。随机命中则没有这个规律，它可能在窗口的任何位置出现。

Q3.2 判据二：区间证据和

只看 d 一个距离会漏。插入和缺失会让证据漂到 d ± 1、d ± 2。这些距离描述的是同一个重复。

所以程序在区间内求和：

Δ(d) = ⌊ 2.3 · √(p · d) ⌋ （p = PI/100，d > 20）
lo = max(1, d − Δ) ，hi = min(maxdistance, d + Δ)

Σt ∈ [lo, hi] nummatches(t) ≥ sum[d]

Δ 是空位随机游走的 95% 范围。2.3 是原程序给定的系数。取 p = 0.1、d = 2000 得 Δ = ⌊2.3 × √200⌋ = 32。区间宽度 65。

d ≤ 20 时不做区间，lo = hi = d。理由：短周期的漂移空间本来就小，扩大到邻域只会引入噪声。

Q3.3 判据三：区域竞争

求和有一个副作用：邻近的强周期也能把和推过门槛。所以还要检查竞争。条件有两条：

  • 区间内没有任何单个距离的匹配数大于 d 的匹配数。
  • 如果有，但那个距离自己的证据已经过期，就不算竞争者。

第二条由"先摘链、再比较"实现。代码在比较之前调用 no_matches_so_unlink_distance。这样一个已经死掉的距离不会阻止候选。

Q3.4 阈值从哪里来

阈值存在两张长 2001 的表里，索引是 min(d, 2000)。PM = 80 时的取值：

dwait[d] 等待sum[d] 证据碱基说明
7185短周期。一组 4 元组命中就接近门槛。
30286切换到 5 元组。等待变长，证据和几乎不变。
1606243切换到 7 元组。指纹变稀有，等待明显变长。
100067386长周期。证据和与 d 近似成正比。
200068818一份拷贝约 2000 个位置，约四成能留下匹配碱基。

为什么证据和随 d 增长：窗口长度是 d + 1。每个位置都可能贡献一次匹配。窗口越长，可数的碱基越多。门槛必须同步提高，否则长周期会过松。

为什么等待时间在 30 和 160 跳变：元组变长，随机命中变稀有，第一次命中需要等更久。表的台阶与元组切换点重合，这不是巧合。

为什么用表而不用公式：精确分布要处理窗口重叠、序列自相关、多重比较。解析式很难写对。用投币模型做模拟，直接存分位数，更可靠也更容易复现。

失效条件

如果真实数据的空位率远高于 PI，Δ 会太窄。证据被分摊到区间外，判据二失败，重复被漏掉。此时应当提高 PI，不要降低 Minscore。

Q4怎样从一条证据得到完整比对

证据只说"位置 i 与位置 i − d 相似"。它不给区间，不给分数，不给拷贝数。第二级要从一条线索得到这四样东西。

问题

比对需要模式串，也需要起止位置。两者都未知。若先固定区间，边界错一点就会漏掉半个重复。

手段

把以种子位置结尾的 d 个碱基当作模式，视为无限重复串，做环绕动态规划。反向扫一次定左边界，正向扫一次定右边界。

理由

局部比对自己决定在哪里开始和结束。列号取模让任意相位都能接上。屏障阻止比对跑到无关区域。

Q4.1 模式从哪里来

程序取 EC = S[i − d + 1 .. i]，正好是以种子位置结尾的一份拷贝，种子在其末尾。

// src/algo.rs:214
for g in 0..size {
    ec[g] = sequence[(start − size + g + 1)];
}

这份拷贝可能带错误。它不是最终模式。Q7 会用共识替换它。但作为比对的起点，它已经足够：它和相邻拷贝的相似度最高。

Q4.2 为什么要"环绕"

模式只存一份。序列有几十份。若把模式复制成几十份，矩阵宽度会随序列长度增长，成本无法接受。

程序换一种做法：列号对 d 取模。走到最后一列之后，下一列回到第 0 列。于是矩阵只有 d 列，却能表达无限重复的模式。

分数沿对角线累积：2、4、6、…、28。第 8 个碱基落在第 0 列，因为 7 mod 7 = 0。序列和模式连续对上，路径就不会中断。

Q4.3 两次扫描

// 反向：从种子之后一行开始，行号下行，序列位置回退
realr = start + 1; r = bw;
while !end_of_trace && realr > 1 && r > 0 { … }

// 正向：从反向阶段的最优行开始，行号上行，序列位置前进
realr = minrealrow − 1; r = 0;
while !end_of_trace && realr < length && r < bw { … }

反向扫描回答"重复从哪里开始"。正向扫描回答"重复到哪里结束"。两次都从种子附近出发，所以两次看到的是同一个结构。

为什么不一次扫完？因为重复可以向种子两侧延伸。起点在种子左边，终点在种子右边。一次单向扫描只能覆盖一侧。

Q4.4 分数下界与 −1000 屏障

局部比对给每格一个 0 下界。没有别的约束时，比对会在任意位置重新开始。这在重复检测里是灾难：它会在远处找到另一个高分区域，报出一个与种子无关的重复。

程序加一个屏障。条件：位置已经越过种子左侧 size（newwrap 用 max(size, 20)），并且分数恰好是 0。此时把 0 改写成 −1000。

// src/algo.rs:642
if realr <= start − max(size, 20) && v == 0 {
    v = −1000;  // 不许在此重新开始
}

−1000 比任何合法分数都小。它不会被 max 选中，因此路径无法从这里穿过。屏障的净效果是：比对必须覆盖种子，只能向两侧延伸有限距离。

Q4.5 为什么每行要扫两遍

列号取模之后，第 0 列与最后一列相邻。这一对相邻关系构成一个环：算第 0 列需要最后一列，算最后一列又需要第 0 列。一行之内无法一次算完。

程序先给环上一个临时值，用这个值算出一行。第二遍把第一遍结束时留在 pleft 里的结果接回环的切点，重算整行。两遍之后，环上的值自洽。

抽象说法

环绕依赖是一个环。程序用一次不动点迭代解它：先猜一个入口值，算一圈，再把出口值接回入口，重算一圈。重复检测的环只有一格宽，所以两遍足够。

带状版本不需要两遍。它每行从带的上边界开始处理，左依赖在带内传递。带的边界就是环的切点。切点之外本来就不算，所以没有环要解。

Q5周期最大 2000，比对太贵怎么办

全列环绕 DP 的每行成本是 d 次单元格计算。取 d = 2000，一行就是 2000 次。重复长度 2000，一共 400 万次。单个候选就要几毫秒。一条染色体有上万个候选，加起来不可接受。

问题

正确路径只会沿对角线走，但矩阵要算全部 d 列。绝大部分单元格是浪费。

手段

只算中心线两侧各 w 列。中心随路径移动。连续 3 行选中同一步就重新居中。

理由

路径偏离对角线的幅度由空位随机游走决定。它的 95% 范围只有 2.3√(p·d)。带外单元格几乎不可能在最优路径上。

Δ(d) = ⌊ 2.3 · √(p · d) ⌋ ，d > 20
w = max(6, Δ(d))
前向带 w′ = min(2w, d / 3)

Q5.2 中心移动引起的边界问题

中心默认沿对角线每行移动一格。重新居中生效时，中心跳到最近三行的匹配列。设本行中心相对上一行移动了 k 列，把 k 规约到 (−d/2, d/2]。行内单元格因此分成三段：

段可用前驱原因
中间主体对角、上、左、0三个前驱都落在上一行的带内。
一个边界格对角、左、0上一行对应位置在带外，无"上"前驱。
另一侧边界左、0上一行对应位置都在带外，只剩"左"。

这就是代码中 max4、max3、max2 三个函数各出现一次的原因。它不是优化，是正确性要求。给带外单元格编一个分数会让路径穿过不存在的区域。

Q5.3 前向带为什么更宽

// src/scan.rs:623
band = max(6, Δ(d));
bandforward = min(2 × band, d / 3);
narrowbandwrap(i, d, band, bandforward, false, 3);

反向阶段的带以种子为中心，路径就在中心附近。正向阶段要走出种子区域，进入尚未探测的部分。路径可能已经偏移了几列。带宽加倍，用来重新捕获路径。

上界 d/3 保证带不会宽到失去意义。硬上界是 MAXBANDWIDTH = 150。2w + 1 > 150 时程序报错退出，退出码 −1。

Q5.4 这个优化的风险

带宽只由 d 和 PI 决定，不由数据决定。如果真实空位率远高于 PI，路径会漂得比带快。重新居中要等连续 3 行的一致匹配。漂移太快时，带可能在居中生效之前就丢掉路径。

症状：分数偏低，或区间被截断。处理办法是提高 PI，让 Δ 变大。不要只降 Minscore，那会放进更多噪声。

Q6怎样取回路径、拷贝数和统计

动态规划只给出分数。报告需要路径、拷贝数、匹配率和周期。四样东西都要从矩阵里取回。

问题

矩阵只存分数，没存方向。若额外存方向矩阵，内存会翻倍。

手段

回溯时重算三个前驱表达式，看哪个等于当前值。拷贝数按跨越模式边界的次数累加。统计用相距一个周期的双指针扫描。

理由

Q6.1 回溯：用等式反推方向

从最高分单元格 (maxrealrow, maxcol) 出发。每个单元格的值必然等于下面三者之一：

对角：S(r−1, j−1) + 相似度(seq[i], ec[j])
上　：S(r−1, j) + δ （序列有插入）
左　：S(r, j−1) + δ （模式有插入）

按这个顺序试。命中哪个就写哪两个字符，然后移动到对应前驱。循环直到分数为 0 或到达矩阵边界。

为什么可以只靠等式：分数是整数，公式固定，所以三个候选值最多只有一个等于当前值。不需要方向矩阵。内存从 L × d 字节降到 0。

Q6.2 带状回溯的两个特殊问题

列号要换算。带内列号 i 与模式列号 c 的关系是 i = w + k，其中 k 是本行中心相对上一行的偏移。回溯时必须用同一个换算去找上一行的前驱，否则会读错格。

0 有两种含义。局部比对里的 0 可能是屏障（−1000 改写前的位置），也可能是真实的比对起点。带状回溯会先做一次判定：检查当前 0 是否等于某个前驱加对应得分。若是，就认为它是合法起点，继续回溯；若不是，就停止。

Q6.4 统计：双指针与距离直方图

回溯得到的四条平行数组是：序列字符、模式字符、序列位置、模式列号。统计阶段用两个指针扫它。

  1. 左指针 lp 移到第一个非空位的模式字符。
  2. 右指针 rp 向前走，直到模式列号与 lp 相同，并且不是空位。
  3. 两个指针逐格前进，比较序列字符。

比较结果分四种：

情形计数说明
两边都不是空位，字符相同match +1同时记录两个序列位置的距离。
两边都不是空位，字符不同mismatch +1同一列上的替换。
一边是空位indel +1插入或缺失。
两边都是空位不计数该列在两份拷贝里都不存在。

每次匹配都产生一个距离 |indexprime[rp] − indexprime[lp]|。程序把它记入直方图。最后取直方图的众数作为报告周期。

为什么用众数

共识长度可能不精确。空位会让实际间距在 period ± 1 之间抖动。众数对抖动不敏感，对系统性偏移敏感。它给出的周期与比对本身一致，因此比候选 d 更可信。

同一次扫描还产出熵。熵由四种碱基的比例算出，范围 0 到 2。纯 AT 重复的熵接近 1，四种碱基均匀的重复接近 2。

Q7周期可能是倍数，怎样定下来

候选 d 来自一次元组命中。它可能是真实周期的 2 倍、3 倍或 7 倍。用倍数做模式，比对同样能得高分，因为周期串的倍数周期也是周期串。

问题

d 只是线索。种子那份拷贝还带错误。直接用 d 做模式，边界与分数都会有偏差。

手段

三重校正：区间内的周期投票、逐列共识投票、用共识重跑一次比对。最终周期取直方图众数。

理由

投票只剔除与显著间距明显不符的候选。倍数周期常常仍在前 3 名之内，所以收尾交给去冗余。共识与重对齐消除种子拷贝的个别错误。

Q7.1 第一重：区间内的周期投票

报告区间确定后，程序在该区间的序列上再统计一次短距离结构。做法如下：

  1. 取所有长度为 2 的元组，按码值分组。
  2. 同一码值的相邻出现给出一个距离。累加到 counts[distance]。
  3. 对 counts 做一次线性拟合，减去趋势项 i × s。
  4. 取前 5 名，存入 sort_multiples。
  5. 候选 d 只要落在前 3 名，就通过。

减去趋势的理由：完全重复的序列里，距离越远，可配对的起点越少。计数天然随距离线性下降。这个下降与"是不是周期"无关，属于背景。减去它，峰值才突出。

这条判据是粗筛，不是精确定理。它能拒绝"倍数太大"的候选，不保证找到最小周期。真实数据里，一个 AT 富集区可能同时报告 2、14、16 三种周期。收尾工作由 Q8 完成。

当 d = 1 时跳过投票。单碱基重复没有内部结构，程序改用另一条判据：区间内出现最多的碱基占比不低于 80%。

Q7.2 第二重：共识序列

比对结果是一张表，每行是"序列的一个碱基对应模式的哪一列"。把同一列的所有碱基收集起来，取多数，就得到共识序列。

列有两种。设模式列号为 c：

  • 对齐列 2c + 1。该列在某份拷贝里存在。
  • 插入列 2c。该列只在部分拷贝里存在，属于插入。

判定规则：

  1. 对齐列：在 A、C、G、T、空位中取多数。
  2. 插入列：若插入比例 ≥ 50%，输出多数碱基；否则输出空位。
  3. 最后压缩：删掉所有空位，剩下的长度就是共识长度 cons_classlength。

为什么插入列要单独判断：一个碱基可能在 7 份拷贝里出现 4 次，在另外 3 份里缺失。这时它应当进入模式，因为多数拷贝有它。直接按列对齐会把它压掉。

Q7.3 第三重：用共识重跑比对

Q8同一重复被报多次，怎样收尾

Q1 到 Q7 只保证"每个候选被正确处理"。它们不保证"同一段序列只报一次"。倍数周期、边界差异、判据的粗筛都会带来重复记录。

问题

输出必须可用于下游。同一位点出现三条记录会导致注释重复、掩码重复。

手段

四步后处理：按周期上限裁剪，按起点排序，按重叠与分数规则去冗余，按发现顺序编号。

理由

排序后重叠记录必定相邻，只需局部比较。规则用"周期成倍数且分数不显著更高"表达信息冗余。

Q8.1 四步

Q8.2 冗余的判定

两条记录 i 与 j，先算区间重叠长度。只有重叠占任一方的 90% 以上，才考虑删除：

overlap / i.length ≥ 0.9　或者　overlap / j.length ≥ 0.9

再看信息是否冗余：

  • i.period 是 j.period 的整数倍，并且 i.score ≤ 1.1 × j.score：删 i。
  • 两者周期相同，并且 i.score ≤ j.score：删 i。

两个条件都不满足时，两条都保留。

Q8.3 为什么这样写

为什么是 90%。同一重复的两次报告，边界常常差几个碱基。要求 100% 重叠会漏掉这种情况。90% 允许边界误差，同时排除"只是路过"的记录。

为什么要求周期成倍数。周期 7 和周期 12 覆盖同一段序列，是两种不同的结构，不能互相删除。只有倍数关系才说明"长周期是短周期的重复"。

为什么是 1.1。如果长周期报告的分数明显更高，说明它捕捉到了短周期看不到的结构。这时不能删。上一节的例子正是这种情况：130 > 1.1 × 108 = 118.8，所以周期 14 保留。

为什么先按起点排序。排序后，与第 i 条重叠的记录一定紧跟在它后面。内层循环一旦发现不重叠就跳出。整个过程是局部的，不需要两两比较全部记录。

Q8.4 对齐文件也要同步

HTML 明细文件在去冗余之前就写好了。删除记录后，文件里还留着它们的比对块。所以程序重写一遍文件：

  1. 逐行扫描。遇到以 Fo 开头的行，读后面两行。
  2. 若第三行含有当前记录的引用串，保留这三行及其后的内容。
  3. 否则跳过整块。
  4. 最后按每 120 条一页切分，文件名加 .1、.2 等后缀。

引用串由起点、终点、周期、拷贝数、共识长度和序号拼成。它是表格与明细之间的锚点。这也是为什么去冗余必须在写表格之前完成。

副作用

去冗余有顺序依赖。先删哪一条，会影响后面能否删除。程序按起点顺序扫描，结果是确定的，但不保证全局最优。这一点与 C 版一致。

3.2 打分矩阵 S 的布局

S 是一维数组，按行连续存放。列数固定为 151，行数是 bw + 1：

S[r][i] = s[r × 151 + i]
bw = min(maxwraplength, n) ，maxwraplength 默认 2 000 000

为什么列数固定：带内列号的最大值是 2w，而 w ≤ 74。取 151 保证够用，同时让下标乘法变成常数。若按 2w + 1 变化，每次访问都要重新算行偏移。

行是循环使用的。反向阶段从第 bw 行往下走，正向阶段从第 0 行往上走。中间的 minrealrow 是两次扫描的接缝。

3.3 模式缓冲区与共识数组

EC 存当前模式，长度是 2 × (2000 + 1)。为什么是两倍：共识可能有插入列，长度会超过原始 d。上限取 MAXPATTERNSIZECONSTANT = 2000。

共识数组有 8 条平行数组：A、C、G、T、空位、插入、列总数、字母总数。列号规则固定：

  • 2c 是第 c 列的插入槽。
  • 2c + 1 是第 c 列的对齐槽。

两倍长度就是为了这个交错布局。取一个碱基的计数时，只需一次下标运算。

3.6 整数分数与浮点边界

热路径上只有整数。分数、列号、位置、距离全是 i32。原因有三条：

  • 整数比较没有舍入误差。同一份输入在任何平台上得到同一路径。
  • 整数加法比浮点加法快，且容易向量化。
  • 回溯靠等式反解前驱。浮点相等判断不可靠，整数相等判断可靠。

浮点只出现在外围：d_range 的平方根、拷贝数的累加、熵、比例统计。这些量不进矩阵，不影响路径。

倍数记录全部得分相同。按 Q8 的规则，i.period 是 j.period 的倍数，且 i.score ≤ 1.1 × j.score，所以删除。区间重叠也是 100%，满足 90% 的条件。

这条对比说明什么

倍数问题不在产生阶段解决。产生阶段容忍倍数，甚至欢迎倍数：去掉它要付出额外的判据，还可能误杀真实的长周期。收尾阶段用一条廉价规则统一处理。

4.8 与 C 版逐字节一致的原因

  • 分数是整数，所有比较没有舍入差异。
  • 浮点只用于输出字段。输出用 C 的 %*.*f 语义，包括 0/0 输出 -nan。
  • 序列描述按原始字节写入，不经过 UTF-8 校验。
  • 管道提前关闭时恢复 SIGPIPE 默认处理，退出状态与 C 版相同。
  • 发布构建启用 fat LTO 与单代码生成单元，扫描循环的机器码接近 C。

5.4 五个常见误读

  1. 把 size 当成周期。size 是共识长度，period 是直方图众数。两者通常相等，但不保证。
  2. 认为 copies 是整数。它是浮点数。末端不完整的部分按比例计入。
  3. 认为 MaxPeriod 就是搜索上限。搜索上限是 maxdistance，受序列长度影响。
  4. 认为 Minscore 决定一切。拷贝数、倍数判据、冗余剔除都可以在分数达标后继续否决。
  5. 认为 0 分表示空白。在带状回溯里，0 可能是合法起点。程序为此单独判定。

§6自查

Q1

一条 1000 bp 的序列，参数 MaxPeriod = 2000。搜索的最大距离是多少？为什么不是 2000？

答案

600。先取 max(2000, 500) = 2000，再取 min(2000, 0.6 × 1000 = 600)，最后取 max(600, 200) = 600。一个周期超过序列长度六成的重复，最多只有一份半拷贝，证据不足。

Q2

为什么距离表里的 nummatches 要按碱基数计，而不是按命中次数计？

答案

因为阈值表是按匹配碱基标定的，也因为连续命中会重叠。一段 100 bp 的匹配产生 97 次命中，但只有 100 个匹配碱基。按次数计会重复计算 96 次，门槛的含义就消失了。

Q3

为什么等待时间判据能排除噪声，却不能单独使用？

答案

等待时间只约束"第一条证据的位置"。随机序列偶尔也会很早出现一条证据，之后不再出现。它不能证明证据总量够。所以要配合区间证据和与区域竞争。

Q4

屏障为什么设在种子左侧 size 处，而不是紧贴种子？

答案

紧贴会切断比对向左延伸的能力。重复的起点常常在种子左侧一份拷贝之外。留出一份的距离，既允许合理延伸，又阻止跑到无关区域。全列版用 max(size, 20)，给小周期留同样的余量。

Q5

带半径由 PI 决定。如果真实空位率是 30%，而 PI = 10，会发生什么？

答案

Δ 按 0.1 计算，只有真实波动范围的约三分之一。路径更早滑出带。重新居中要等连续 3 行的一致匹配，漂移太快就追不上。结果是分数偏低或区间被截断。应当提高 PI。

Q6

为什么共识要比对两次才能得到？

答案

第一次比对需要模式。此时唯一可用的模式是种子那份拷贝，它带错误。第一次比对的结果用于逐列投票，得到共识。共识更干净，但它的长度和相位可能与原模式不同，所以要用它重跑一次，才能得到与它一致的分数、区间和拷贝数。

Q7

为什么去冗余要求"周期成倍数"？如果两条记录周期不同但区间几乎相同，应当删哪一条？

答案

区间相同不代表信息冗余。周期 7 与周期 12 描述两种不同的重复单元，都可能是真实结构。倍数关系才说明长周期是短周期的重复。周期不同且不成倍数时，两条都保留。

Q8

关闭去冗余后，三条测试序列分别产生 2、3、3 条记录。这说明哪个阶段最需要后处理？

答案

倍数周期在多处产生：元组命中的距离、周期投票的前 3 名、共识长度。去掉它们要付出误杀的风险。因此程序选择容忍，把统一收尾放在最后一步。这也是"先产生后清洗"这个结构决定的直接后果。
