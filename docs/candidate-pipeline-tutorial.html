trfrs 第一级流水线七步走查

TRF 把检测拆成两级：第一级便宜，只负责回答"这里可能有一个周期为 d 的重复吗"；第二级昂贵，才做真正的比对。本教程沿着一个碱基的旅程走完第一级的每一步，看候选从一条短串命中开始，怎样被记账、被检验、最后被放行。

对象：src/scan.rs 前置阅读：docs/trf-problem-to-code.html Q1–Q3（可选） 运行示例：tests/data/small_test.fasta 第一条序列

§0总览：候选是什么，从哪来

候选（candidate）是一个二元组 (i, d)：位置 i 处发现证据，提示"这里可能存在周期为 d 的串联重复"。它不是结论——随机序列也会产生候选。候选只是比对的入场券：拿到券的位置进入第二级做动态规划；拿不到的，程序从头到尾没有为它开过一张矩阵。

第一级流水线的完整链路如下。每个方框对应本教程的一节：

本教程的走查约定

全程使用同一条 35 bp 测试序列 TCATCGGTCATCGGTCATCGGTCATCGGTCATCGG（TCATCGG × 5），参数取人类 DNA 默认组合 2 5 7 80 10 50 2000。每一步都给出：它在做什么、对应哪段代码、在这条序列上发生了什么。

§1预备：把阈值装进内存

流水线跑起来之前，有两件事要先备好。它们不产生候选，但决定了后面每一步的"尺度"。

1.1 距离表按 maxdistance 建

每个可能的周期长度 d（1 到 maxdistance）一张小表，另加一条按 d 排序的双向链表和标签数组。容量一次性分配，运行期不再扩容。

1.2 阈值表来自随机模型

对每个 d，程序需要回答"多少证据才算多"。答案不靠拍脑袋：用投币模型（每个位置以 PM/100 概率匹配、PI/100 概率发生插入缺失）做模拟，取分位数，预生成两张长 2001 的表：

  • wait[d]——等待时间门槛（窗口打开后，第一条证据最晚何时出现）；
  • sum[d]——区间证据和门槛（匹配碱基数下限）。

PM = 80 时的代表性取值：

dwait[d]sum[d]说明
7185短周期。一组 4 元组命中就接近门槛。
30286切换到 5 元组，等待变长。
1606243切换到 7 元组，指纹变稀有。
100067386证据和与 d 近似成正比。
200068818窗口长约 d，门槛必须同步提高。

表的台阶出现在 d = 30 和 d = 160——正好是元组长度切换点。这不是巧合，§2 会解释。

§2第 1 步：逐位扫描，滚动编码

在做什么

把序列变成可索引的"指纹"。每个位置都要能 O(1) 地回答："我手里的 k 个碱基，最近一次出现在哪里？"

怎么做

A/C/G/T 编码为 0/1/2/3，长度 k 的短串就是一个 4 进制整数。每前进一位，丢最高位、补最低位，滚动更新。

为什么成立

编码是每次一位的常数操作，没有回溯、没有哈希碰撞处理。成本全部落在扫描本身。

主循环 scan_sequence() 每前进一个位置 i，维护一个 7 元组码：

// src/scan.rs:767
code = (code % FOUR_TO_THE[6]) × 4 + index[sequence[i]]

短元组不用单独扫：7 元组码取模即得后缀。

// src/scan.rs:771
tuple_code[3] = code           // k = 7
tuple_code[2] = code % 4⁵      // k = 5
tuple_code[1] = code % 4⁴      // k = 4

为什么是 4、5、7 三档？因为距离越大，需要越稀有的指纹。随机序列中两个指定位置共享一个 k 元组的概率是 4−k：k=4 时 1/256，k=7 时 1/16384。距离 d 的窗口长约 d，期望证据数 ≈ n·W·4−k，要让它不随 d 失控，k 必须随 d 增大：

元组长度 k负责的距离区间理由
41 到 29副本短，容不下长精确串。
530 到 159居中。误报率降到 1/1024。
7160 到 maxdistance长副本提供长精确串，用最稀有指纹。
非 ACGT 字符

遇到 N 等字符时滚动码作废，程序重置编码，等凑满连续 7 个好字符才重建（src/scan.rs:737）。副作用：跨 N 的重复会被切成两段，第一级不会把 N 两侧接起来。

落点　主循环 src/scan.rs:692，编码与元组更新 src/scan.rs:756

§3第 2 步：历史链找距离

在做什么

周期是待求量。如果把它当未知数，比对要对每个 d 重做。第一级要先把"周期问题"降维成"距离问题"。

怎么做

每个元组码挂一条历史链，记录这个码最近几次出现的位置。新命中到达时，沿链回访旧位置，差值 d = i − 旧位置 就是距离。

为什么成立

距离是周期的一种（周期 d 的重复必然产生距离 d），反过来不成立。这个不对称让"只记账、不判定"成为可能。

在位置 i 得到码 c 之后，程序做三件事：

// src/scan.rs:794（抽象形式）
h = 新历史槽
history[h] = { location: i, previous: head[c], code: c }
head[c] = h          // 三步：写槽、接链、改头指针

// 然后沿 previous 走链：
while y != 0:
    d = i − history[y].location
    if d > tuple_max_distance[g]:  在此断链，后面更远，停
    if d ≤ tuple_max_distance[g−1]: 归更短的元组管，跳过
    else:                          process_candidate(i, d, k)   // → §4

第二个截断条件保证一个距离只由一个元组尺寸负责——7 元组的命中不会在 d = 10 上重复记账，那里归 4 元组管。

历史槽放在环形数组里，总容量 2 × tuple_max_distance + 4，写满覆盖最旧的。被覆盖的槽位置必然更旧、距离已超上限，所以不会漏近处的证据。

35 bp 走查

位置 1–4 的元组 TCAT，在位置 8–11 再次出现。当 i = 11 时，程序从哈希表取到 TCAT 的历史链，发现旧位置 4，算出 d = 7。这是本序列的第一条证据。注意此刻还没有任何"这是重复"的判断——只是登记了一个 (11, 7, 4)。

落点　链遍历与候选分派 src/scan.rs:799

§4第 3 步：距离表记账

在做什么

每条线索都往表里写一笔。若不加控制，条目随时间无限累积，遍历与判据都会失控。

怎么做

每个 d 的小表只保留滑动窗口内的条目；相邻命中合并成一段；计数按"匹配碱基"而非命中次数。

为什么成立

证据有时效：太旧的匹配说明重复已经中断。合并使一段长精确匹配的条目数从 O(L) 降到 O(1)。

证据条目是一个二元组 (location, size)：location 是匹配段的最右位置，size 是这段连续匹配的长度。窗口左端：

// src/scan.rs:138
windowleftend = min(location − d, location − 20) + 1

含义：窗口至少覆盖一份完整拷贝；短周期（d < 20）再给 20 个位置的余量。插入新证据前，先从窗口左端丢弃过期条目，并且要同步扣减匹配碱基数：

// src/scan.rs:144
match_count −= entry[low].size;   // 不能只减条目数！
entry_count −= 1;

新命中若与上一条目相邻，就合并而不是新开：

// src/scan.rs:157
if entry[hi].location == location − 1:
    entry[hi].location += 1
    entry[hi].size += 1
    match_count += 1        // 只加 1：4 个碱基里 3 个已数过
关键细节：计数单位

match_count 数的是匹配碱基。一次 4 元组命中贡献 4；两个相邻命中合并且只多贡献 1。一段 100 bp 的精确匹配，最终只剩 1 个条目、size = 100。这个语义直接决定判据的量纲——§6 的门槛说"匹配碱基至少 5 个"，不是"命中至少 5 次"。

35 bp 走查 
i = 11:  distance[7].entry = { location: 11, size: 4 }   match_count = 4
i = 12:  元组 CATC 命中位置 5，与上一条相邻
         合并 →  { location: 12, size: 5 }               match_count = 5

到 i = 12，d = 7 的账本上已有 5 个匹配碱基——恰好够到门槛 sum[7] = 5。这是合并机制的直接效果：孤立命中差 1 个碱基过不了线，相邻合并就过了。

落点　记账 src/scan.rs:133

§5第 4 步：活跃清单

在做什么

判据需要在 [lo, hi] 区间内对所有距离求和、比较。扫描全部 2000 张表不可行，大部分表是空的。

怎么做

只有非空的 d 参与工作。它们串成按值排序的双向链表；另设每 50 个距离一组的标签数组做插入锚点。

为什么成立

遍历成本变成"区间内的活跃距离数"而不是 O(maxdistance)。摘链保证死掉的距离不再产生任何成本。

三条维护规则：

  1. 入链：d 的表第一次收到证据时插入链表。为避免每次从链表头扫描，先查 tag[d/50]——游标比 d 小就从游标处接上，比 d 大就沿 link_down 找第一个小于 d 的活跃距离。插入平均成本接近常数。
  2. 摘链：判据遍历邻居时顺带清理过期条目（no_matches_so_unlink_distance，src/scan.rs:225）。条目清空就地摘链。这就是为什么活跃距离数通常只有几十。
  3. 同步标签：摘链时如果 tag[t] == d，要把受影响组的游标回落到 link_down，否则游标会指向已经不在链上的 d。

内存上，全部表一次分配，每个 d 容量 max(d, 20) + 1，总计约 maxdistance²/2 条 × 8 字节。maxdistance = 2000 时约 16 MB——固定成本，可接受；这也解释了 MaxPeriod 为什么是 2000 而不是 100000。

落点　入链 src/scan.rs:174，摘链 src/scan.rs:225，标签 src/scan.rs:212

§6第 5 步：三条判据——什么时候相信证据

在做什么

证据只说明"两个位置共享一段短串"。随机序列也会产生证据。必须有一个可计算的显著性判断。

怎么做

三条判据：等待时间、区间证据和、区域竞争。阈值全部查表，索引是 min(d, 2000)。

为什么成立

真重复有三个可测特征：证据来得早、总量大、邻域内最强。三条判据各抓一个。随机命中很难同时满足。

判据主体是 new_meet_criteria_3(d, i, tuplesize)（src/scan.rs:403）。三条依次是：

6.1 判据一：等待时间

left = max(0, i − max(d, 20))
first_location ≤ left + wait[d]
first_location = 最老一段证据的起点 = entry[low].location − size + k

真重复的证据应该"来得早"：窗口一打开就该出现。随机命中可能在窗口任何位置，落进前 wait[d] 个位置只是小概率事件。

6.2 判据二：区间证据和

Δ(d) = ⌊ 2.3 · √(p · d) ⌋　（p = PI/100，d > 20；d ≤ 20 时区间只有 d 自己）
lo = max(1, d − Δ)，hi = min(maxdistance, d + Δ)
Σt∈[lo,hi] match_count(t) ≥ sum[d]

为什么不是只看 d 自己？因为插入和缺失会让后续副本的证据漂到 d±1、d±2——这些距离描述的是同一个重复。Δ 是空位随机游走的 95% 范围：p = 0.1、d = 2000 时 Δ = 32。同时程序还会检查主距离自己的 match_count 是否已单独达标（main_d_matches ≥ min_krun_matches），达标就不必做区间遍历。

6.3 判据三：区域竞争

区间求和有副作用：邻近的强周期也能把和推过线。所以要求 d 在邻域内没有竞争者：

  • 沿链表向下、向上遍历区间内的活跃距离；
  • 任何单个距离的 match_count 严格大于 d 的，d 出局；
  • 遍历前先对邻居执行摘链清理——已经死掉的距离不算竞争者，不能阻止候选。
35 bp 走查（i = 12, d = 7）
判据实际值结果
等待时间first = 11，上限 max(0, 12−20) + 18 = 18通过
区间证据和d ≤ 20，区间只有 7 自己，和为 55 ≥ 5，通过
区域竞争区间内只有 7 一个活跃距离通过

三条全过，(12, 7) 拿到入场券。

失效条件

判据二的区间宽度 Δ 由 PI 决定。如果真实数据的空位率远高于设定的 PI，证据会被摊到区间之外，判据二失败，重复被漏掉。此时应当提高 PI，而不是降低 Minscore。

落点　判据主体 src/scan.rs:403，摘链在判据内 src/scan.rs:435

§7第 6 步：最佳周期表——廉价的二次筛选

通过三条判据只说明"值得做一次比对"。但一个长重复天然会被它的所有倍数距离反复触发：周期 21 的重复会以 d = 7、14、21 各触发一次。比对是贵的，能省则省。

程序维护一张"已知最佳周期表"：每条已确认记录保存它的区间和前 5 个显著周期，最旧的在尾部；终点早于 start − 2 × maxdistance 的记录删除。规则（src/scan.rs:610）：

  • 仅当 d > 250 时执行检查——短距离重复便宜，不值得这道手续；
  • 若当前位置已被某条记录覆盖，且 d 不在那条记录的前 5 个周期里 → 跳过；
  • 否则放行。
为什么容忍倍数候选

注意筛选只在入场前做"减法"，而且非常保守：倍数候选如果真的进入第二级并各自通过，产生多条重叠记录，统一交给后处理的去冗余规则处理（区间重叠 ≥ 90%、周期成倍数、分数不高于 1.1 倍才合并）。产生阶段不做精细判定，收尾阶段一条廉价规则统一收口。

落点　最佳周期表 src/scan.rs:319，调用点 src/scan.rs:610

§8第 7 步：放行——把接力棒交给第二级

全部门槛通过后，process_candidate 的后半段（src/scan.rs:615）接管：

  1. 比对：以位置 i 结尾的 d 个碱基为模式，做环绕动态规划。d ≤ 20 走全列版本；否则走窄带版本，带宽由空位随机游走范围决定。反向扫一次定左边界，正向扫一次定右边界。
  2. 拷贝数检查：copies 太低直接放弃（d ≤ 50 要求 ≥ 1.9，随 d 递减到 1.8）——只覆盖半份拷贝的"重复"没有报告价值。
  3. 倍数投票：对区间做周期投票，d 必须是前几个显著间距之一。
  4. 共识与重对齐：从比对直方图提取共识序列，用共识长度再跑一次比对。最终周期由重对齐结果决定，不由候选 d 决定。
  5. 输出：区间长度 ≥ minsize 且分数 ≥ minscore 才写入报告。

第二级的细节（环绕 DP、带状回溯、共识投票、去冗余）见《从问题到代码》Q4–Q8，本教程不再展开。这里只需要一个数字感受第一级过滤的力度：

量级：19 比 1

35 bp 测试序列上，第一级共登记 58 次证据（d = 7 记 25 次、d = 14 记 18 次、d = 21 记 11 次、d = 28 记 4 次），只有 3 个 (i, d) 通过全部判据、各开了一张比对矩阵。放到基因组上，这个比例就是"算得完"与"算不完"的差别。

回到最初的问题

"先证据，后比对"在这条序列上具体表现为：58 次零成本的记账，换 3 次昂贵的比对。证据是必要条件（真重复必然留下精确短串），判据负责把随机噪声挡在门外，比对只对幸存者做最终裁决。

10.2 自测题

Q1

为什么证据计数用"匹配碱基"而不用"命中次数"？如果换成命中次数，哪类候选会受益？

参考答案

相邻命中重叠 3 个碱基。按次数计，一段长精确匹配会虚增计数，短而密的随机重合更容易凑够门槛；按碱基计，计数与实际相同序列的长度成正比，物理含义清楚，且门槛（如 sum[7] = 5）对任何元组长度都是同一量纲。换成次数，短元组（k=4）的随机重合最受益，误报会上升。

Q2

真实重复的错配率约 20%。为什么可以确信第一级不会漏掉它？

参考答案

只要某份副本里存在连续 k 个无错碱基，这个元组就会在下一份副本的对应位置再次出现，产生距离 d 的证据。0.8⁴ ≈ 0.41，一条几百 bp 的重复几乎不可能连一个 4 连无错段都没有。距离更大的区间用 k = 5、7 的更长指纹，由更长的无错段（概率更低但重复区总长度更长）覆盖。判据的区间求和（Δ(d)）进一步容忍 indel 引起的漂移。

Q3

判据三为什么必须"先摘链、再比较"？如果反过来会发生什么？

参考答案

摘链清理会把窗口内条目已全部过期的死距离移出链表。若不先清理，一个早已死掉但历史计数仍高的邻居会被误判为"竞争者"，阻止当前候选放行——明明它自己已经没有任何窗口内的证据。先摘链保证比较只在"仍然活跃"的距离之间进行。

Q4

d ≤ 20 时不做区间求和（区间只有 d 自己），d > 250 才查最佳周期表。这两个"简化"分别省了什么、冒险了什么？

参考答案

d ≤ 20：短周期漂移空间小（Δ 公式在 d ≤ 20 时区间本来就近乎单点），扩区间只引入噪声；冒险是极小，因为短距离证据量大，门槛 5 个碱基很快达到。d ≤ 250 不查周期表：短距离比对便宜（全列 DP 只对小 d 使用），逐个查表反而开销占比高；冒险是同一个短重复可能被 2d、3d 多触发几次，多开几张矩阵，但这些冗余记录最终由去冗余阶段统一收口——花钱买个简单，值得。

Q5

如果把 maxdistance 从 2000 提到 10000，第一级会有哪些直接后果？

参考答案

内存：距离表总量 ∝ maxdistance²/2，翻 5 倍（2000 → 10000）意味着约 16 MB → 400 MB 的固定分配。历史槽：容量 ∝ tuple_max_distance，同样显著增长。7 元组负责的距离上限拉长，链遍历更久。同时阈值表 wait[]/sum[] 只有 2001 项，d > 2000 需要重新生成表。这就是 MaxPeriod 上限停在 2000 的工程原因。
