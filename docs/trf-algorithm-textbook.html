1问题：什么是串联重复

串联重复（tandem repeat，下文简称 TR）是一段短序列连续出现多次的结构。各次拷贝首尾相接，中间不插入其他序列。

这个例子有三个数：

  • 周期 p = 7。周期是一份拷贝的长度。
  • 拷贝数 c = 5。拷贝数是份数。
  • 区间长度 L = 35 = p × c。

1.1 三类噪声

真实基因组的重复不整齐。噪声有三类：

  1. 替换。某一份拷贝的一个碱基变成别的碱基。
  2. 插入与缺失。某一份拷贝多一个或少一个碱基。后面的拷贝会整体移位。
  3. 边界模糊。重复在哪里开始、在哪里结束，没有标记。

因为第 2 类噪声，单纯的字符串比较会失效。周期相同、只差一个碱基的两段序列，在字符层面完全不同。

关键认识

找 TR 不是“找相同的子串”。它是“找一个周期，使该周期与区间的比对得分最高”。
所以问题的核心是比对，不是匹配。

1.2 形式化

给定序列 S[1..n]，求三样东西：

  • 一个周期 p，1 ≤ p ≤ MaxPeriod；
  • 一个区间 [a, b]；
  • 一条比对。这条比对把 S[a..b] 与一个长度 p 的循环模式对齐。

目标是让比对得分最大，并且得分不低于 Minscore。

“循环模式”是本书最重要的概念。模式长度是 p。比对到模式的最后一个字符后，下一个字符回到模式的第一个字符。模式像一条首尾相接的带子。

1.3 为什么暴力法不行

不妨估算一下暴力法的成本。序列长度 n，最大周期 P。

  • 周期的取值有 P 种。
  • 起点有 n 种。
  • 每个起点的比对长度可达 n。

三项相乘是 O(n²P)。对人类染色体（n ≈ 2.5×10⁸，P = 2000）而言，这个数字无法接受。

所以程序必须先把候选压到很少。见第 2 章。

2总览：过滤加验证

TRF 使用过滤加验证（filter and verify）的结构。先用便宜的规则排除绝大多数位置，再对少量候选做昂贵的比对。

1
读取序列FASTA 解析，转成大写 ACGT 字节数组，下标从 1 开始。
2
元组扫描用长度 4、5、7 的短串产生候选 (位置 i, 距离 d)。成本与 n 成正比。
3
统计判据用概率模型算出的阈值，丢掉随机噪声。成本很低。
4
环绕动态规划对通过判据的候选做完整比对，得到分数、区间、拷贝数。
5
共识与重对齐从比对推出共识序列，再用共识重跑一次比对。
6
周期确认与统计确认 d 不是真周期的倍数；算匹配率、熵、最终周期。
7
去冗余与输出删掉被更短周期完全解释的重复，写 HTML 与 .dat 文件。

各层的职责可以用一句话概括：

层输入做什么成本
扫描整条序列产生候选 (i, d)≈ c₁·n
判据候选 (i, d)保留少量可信候选≈ c₂·n
DP少量候选算出最佳比对≈ c₃·n·w，w 是带宽
后处理重复列表确认、统计、去冗余O(m log m)，m 是重复数
为什么这样分工

便宜的判据只要看“元组重复出现了几次”。昂贵的 DP 要填一张表。把判据放在前面，DP 的次数就从 nP 降到接近 n 的常数倍。

3.2 局部比对：分数下限是 0

比对是局部的。任何单元格的分数不会低于 0。分数掉到 0 时，比对从这里重新开始。

这条规则很重要。它让程序不必预先知道重复的起点。它也带来一个副作用：回溯时必须判断“这个 0 是真终点，还是被截断的假 0”。第 9 章讲这件事。

3.3 PM 与 PI 为什么不进分数

常见误解

PM=80 不表示“匹配得 80 分”。它表示“在随机序列模型里，两个碱基相同的概率是 0.80”。
PM 与 PI 只进入统计模型：阈值表和带宽公式 d_range。打分只用 α、β、δ。

阈值来自两张静态表：WAITDATA80 与 SUMDATA80。表按周期 d 索引。第 6 章用它们。

3.4 派生量

程序在初始化时算出几个派生量。它们决定后面的成本和精度。

maxdistance：实际可检测的最大周期

src/state.rs:342–347
let mut maxdistance = params.maxperiod as i32;
if maxdistance < 500 { maxdistance = 500; }
maxdistance = min(maxdistance, (length as f64 * 0.6) as i32);
maxdistance = max(maxdistance, 200);

三步的含义：

  1. 下限 500。用户给的小值不会让程序失去检测能力。
  2. 不超过序列长度的 60%。比序列还长的周期没有意义。
  3. 下限 200。短序列也能查较长的周期。

对 35 bp 的测试序列，maxdistance = max(min(500, 21), 200) = 200。

pindel 与 d_range：允许多大的相位漂移

pindel = PI / 100。在 PI=10 时它等于 0.1。然后用一个平方根公式算出 95% 的随机游走范围。

src/state.rs:477–480
pub fn d_range(&self, d: i32) -> i32 {
    (2.3 * (self.pindel * d as f64).sqrt()).floor() as i32
}
d_range(d) = ⌊ 2.3 · √(pindel · d) ⌋ pindel = 0.1 时：d_range(35) = 4，d_range(200) = 10，d_range(2000) = 32。这就是后面“带宽”的来源。

bw：动态规划的行数上限

DP 的每一行对应序列的一个位置。行数不能超过序列长度，也不能超过用户用 -l 给出的上限（单位是百万碱基，默认 2）。

let bw = min(params.maxwraplength as usize, seq.length);

所以对短序列，bw = n。对染色体级别的输入，bw = 2,000,000。

3.5 没有最小周期门槛

源码里 minsize 固定为 1，从不被命令行修改。最终判断是 classlength >= minsize，因此它永远成立。

换言之，程序只限制周期的上限（MaxPeriod），不限制下限。周期 1 的重复（同一碱基连续出现）也会被检测，由第 11.5 节的规则单独处理。

5第一层：元组扫描

这一层回答一个问题：哪个周期值得检查？

答案来自一个观察。若某处有周期为 d 的重复，则序列中相隔 d 的两个短串会相同。短串越长，巧合越少。所以程序用 4、5、7 三种长度的短串做证据。

5.1 三种元组长度

    self.tuple_size[1] = 4;  self.tuple_max_distance[1] = 29;
    self.tuple_size[2] = 5;  self.tuple_max_distance[2] = 159;
    self.tuple_size[3] = 7;  self.tuple_max_distance[3] = self.maxdistance;

元组长度哈希槽数 4^k负责的周期 d理由

为什么按距离分段

同一个周期会被多个元组长度看到。若三种都处理，成本翻三倍，结果不变。
规则是：每个距离只交给“能覆盖它的最短元组”处理。短元组便宜，长元组昂贵，这样总成本最低。

代码里的判断条件是 d > tuple_max_distance[g-1]。第 g 种元组只处理“比上一种元组的覆盖上限更远”的距离。

}

5.2 滚动编码

程序把 A、C、G、T 编码成 0、1、2、3。任意一段长度 k 的串就是一个 4 进制整数，值域 [0, 4^k)。这个整数可以直接当数组下标。

为避免每个位置都重算 k 个字符，程序用滚动更新。取低 k−1 位，左移两位（乘 4），再加新字符。

src/scan.rs:766–769
code = (code % FOUR_TO_THE[(self.tuple_size[self.nts as usize] - 1) as usize]) * 4
     + self.index[self.sequence[i as usize] as usize];

滚动编码维护的是最长的那种元组（7 个碱基）。其他长度从它截取低位。

src/scan.rs:771–774
self.tuple_code[self.nts as usize] = code;
for h in (1..self.nts as usize).rev() {
    self.tuple_code[h] = code % FOUR_TO_THE[self.tuple_size[h] as usize];
}

例如 code 的最低位 4 个碱基，就是长度 4 的元组的编码。取模 4^4 = 256 就把它截出来了。

5.3 哈希表加历史链

每种元组长度有自己的一张哈希表和一条环形缓冲。

  • tuple_hash[g][code] 存最近一次出现该元组的槽位号。0 表示没有。
  • history[g] 是一条环形缓冲。每条记录有 3 个字段：位置 location、上一个同码槽位 previous、编码 code。

插入新位置的步骤固定为 4 步。位置 i 到达时执行一次。

  1. 算出三种长度的编码。
  2. 取回旧链头 y = tuple_hash[g][code]。
  3. 把新记录写进槽位 h，让 tuple_hash[g][code] = h。h 是环形缓冲的下一个空槽。
  4. 沿旧链 y 走，对每个节点算出 d = i − location，交给判据。

环形缓冲的容量是 2·(max distance + 1) + 2。它只需要装下“窗口内的位置”。超窗口的节点必然被截断，所以不必保存。

src/scan.rs:706–713
for g in 1..=nts {
    let codes = FOUR_TO_THE[self.tuple_size[g] as usize] as usize;
    let hsize = 2 * (self.tuple_max_distance[g] + 1) + 2;
    self.tuple_hash[g] = vec![0i32; codes];
    self.history_size[g] = hsize;
    self.history[g] = vec![HistoryEntry::default(); hsize as usize];
}

5.4 非 ACGT 字符的处理

序列里可能有 N 或其他字符。程序把它们当分隔符。

  • 遇到非 ACGT，记下位置 badcharindex，并置 build_entire_code = true。
  • 重新找到连续 mintuplesize（这里是 4）个合法字符后，才恢复扫描。
  • 编码重建时从 badcharindex + 1 开始累积。

这条规则保证候选不会跨越 N 区。跨 N 的“重复”没有生物学意义。

5.5 复杂度

主循环对每个位置做 nts（3 或 4）次哈希查找。每次查找还要走链。链的深度取决于同一元组在窗口内出现了多少次。

  • 随机序列：链很短，平均常数。
  • 重复序列：链会变长，但被 d > tuple_max_distance[g] 截断，深度上限是窗口内的同码次数。

所以总成本接近 O(n)。第 14 章给出完整的成本表。

6.1 距离记账：窗口内的匹配

每个周期 d 有一份列表，记录最近出现的匹配位置。列表是一个环形队列，容量 max(d, 20) + 1。

src/scan.rs:133–171 · add_tuple_match_to_distance_entry()
let windowsize = max2(d, 20) + 1;
let windowleftend = min2(location - d, location - 20) + 1;
// 逐出左端过期的条目，并从 nummatches 中减去它们的大小
if list.entry[hi].location == location - 1 {
    list.entry[hi].location += 1;   // 相邻元组：延长现有条目
    list.entry[hi].size += 1;
    list.nummatches += 1;
} else {
    /* 新条目 */
    list.nummatches += size;
}

三个要点：

  1. 窗口左端是 min(i − d, i − 20) + 1。至少看一个完整周期，也至少看 20 个碱基。
  2. 相邻元组合并。若新位置正好接在上一条之后，只把条目的长度加 1。这让一次连续匹配只占一个条目。
  3. nummatches 统计窗口内“被匹配元组覆盖的碱基数”，不是元组个数。一次 4 元组贡献 4。
为什么用 min(i−d, i−20)

7第三层：环绕动态规划

7.1 为什么叫“环绕”

普通比对把序列和一条固定模式对齐。模式有明确的第一个字符和最后一个字符。

这里的模式是循环的。比对到最后一列后，下一列回到第 0 列。所以一张表可以同时覆盖同一模式的任意次拷贝。

这一步解决了什么

相位问题消失了。
程序不需要猜“重复的第一份从模式的第几个碱基开始”。任何相位都会被表自动吸收。

7.2 单元格的含义

S[r][c] 表示：在序列第 r 位、模式第 c 位结束的最佳局部比对得分。

三条转移路径：

路径动作得分变化
对角线序列取一个碱基，模式取一个碱基+α（相同）或 +β（不同）
上序列取一个碱基，模式不动+δ（序列相对模式多一个碱基）
左序列不动，模式前进一个+δ（模式相对序列多一个碱基）
S[r][c] = max( 0, S[r−1][c−1] + mm, S[r−1][c] + δ, S[r][c−1] + δ ) 四项分别是：重新开始、对角线、上、左。取 0 保证局部性。

7.3 代码里的方向

backward 半边覆盖候选点左侧，所以行号倒着填。此时“上一行”是 r+1，公式里的 r−1 全部换成 r+1。

三个变量在这里代替二维下标：

  • diag[c]：对角线前驱 S[r+1][c+1] 已加上 mm。每行结束时整体移位一位。
  • up[c]：上方前驱 S[r+1][c] + δ。
  • pleft：左方前驱 S[r][c+1] + δ，随扫描方向在内层滚动。

7.4 为什么每行扫两遍

注意 pleft 的依赖在同一行内，而且是循环的。列号取模后，第 size−1 格的左邻是第 0 格。一次扫描无论从哪头开始，都无法同时满足这两个依赖。

程序的解法是扫两遍：

  1. 第一遍：pleft 初始化为 δ，相当于假设第 0 格为 0，先得到一版结果。
  2. 第二遍：接着第一遍的结尾继续。此时 pleft 正好是第一遍第 0 格加 δ，恰好用在第 size−1 格上；其余格子用第二遍自己算出的左邻。

两遍之后，除回绕处用的是第一遍的值外，每个格子的三个前驱都是准确的。代价是每行算两次，只影响常数因子。

为什么不用两个行缓冲

两遍法只多用 3 个标量，不需要额外的行缓冲。
代价是两次乘法与两次写内存。在 1999 年的硬件上，这个折中很划算。移植版保留它，是为了与 C 版逐字节一致。

7.5 屏障：−1000

局部比对允许随时从 0 重新开始。这个自由在环绕 DP 里会造成问题：回溯可能一直走到序列开头，得到一个无意义的比对。

所以程序在特定区域把 0 改写成 −1000。−1000 比任何真实分数都小，所以它等价于“禁止通行”。

方向屏障位置作用
backwardrealr ≤ start − max(size, 20)禁止比对在候选点之前 max(size, 20) 个碱基以外开始
forwardrealr ≥ start禁止比对在候选点之后重新开始

结果：比对只能有一个起点，且起点落在候选点之前 max(size, 20) 个碱基以内。回溯因此有确定的终点。

屏障不切断好路径

屏障只改写得分为 0 的格子。得分大于 0 的格子照常保留。
所以一条连续匹配的路径可以穿过屏障区，只有“想重新开始”的路径被挡住。

7.6 两个半边

表很大，一次只能朝一个方向填。程序把表分成两个半边，在候选点处汇合。

backward 半边的起始行是 r = bw，整行填 0。forward 半边的起始行是 r = 0，整行填 backward 得到的最大分。这样 forward 可以从任意模式列继续，不受相位约束。

循环在两种情况下停止：

  • 整行都是屏障（end_of_trace 保持为真）。
  • 到达序列边界或行数上限。

8带状优化

8.1 为什么需要

完整矩阵有 size 列。size 最大 2000。若每个候选都填 bw × size 个格子，成本会回到不可接受的水平。

但真正有用的格子只在对角线附近。因为比对里插入缺失很少，模式每读一个碱基，序列也基本前进一个碱基。偏离对角线的距离就是相位漂移。

第 3 章已经算出漂移的 95% 范围 d_range(d)。它随 √d 增长，远小于 d。

8.2 带宽

w = max( MINBANDRADIUS , d_range(d) ) , MINBANDRADIUS = 6
每行只算 2w + 1 个格子 d = 35 时 w = 6，每行 13 格。d = 2000 时 w = 32，每行 65 格。上限是 149（MAXBANDWIDTH = 150）。

8.3 中心如何移动

每行开始时程序先算中心偏移量 k：本行中心相对上一行中心的位移。把它归一化到 [−size/2, size/2]。

k 决定本行的格子怎么对齐上一行，也决定每个格子还剩几个前驱。

  • 正常步进。backward 半边每行中心减 1，得 k = −1；forward 半边每行中心加 1，得 k = +1。此时每行只有一两个格子缺少某个前驱。
  • 重新居中。k 可以取更大的绝对值，带的跳跃更明显，两端的特殊格子随之变多。
  • k = 0：中心不动，是正常步进的特例。

格子按可用前驱分三类：

  1. 普通格：三个前驱都在带内，取 max(0, diag, up, left)。
  2. 边界格：缺“上”或缺“对角线”，只剩两个前驱。
  3. 边缘格：只剩“左”，相当于继续插入。

11周期确认

11.1 问题：d 可能是倍数

假设真实的周期是 3，序列是 ACG ACG ACG ACG。距离 6 也有大量匹配，因为 6 是 3 的两倍。若不检查，程序会同时报告 3 和 6。
更糟的情况是只报告 6，因为 6 的证据在窗口里更集中。

11.2 做法：区间内的距离直方图

程序取出已找到的重复区间，统计所有“相同二元组”之间的距离。

只有 16 个桶（AA、AC、…、TT），比元组扫描的哈希表更小更便宜。区间通常只有几百个碱基，直接全算也不贵。

11.3 去趋势

距离 i 上能出现的配对数带有一个与周期无关的线性成分：距离越小，可配对的位置越多。这个成分会干扰排名，先把它去掉。

src/scan.rs:88–104

let s = (n * xysum - xsum * ysum) / (n * x2sum - xsum * xsum);
for i in 1..=end {
    counts[i] -= i as f64 * s;
}

s 是标准最小二乘公式的斜率（模型含截距）。程序只减去斜率部分 i·s，常数项保留。若背景随 i 下降（s < 0），减去 i·s 正好把背景拉平。剩下的峰值才反映周期性。

不去趋势会怎样

原始直方图里，小距离上的噪声天然偏多。真周期若排在较大的距离上，可能被这些噪声挤出前 5 名。
拉平背景后，峰值无论落在哪个距离上，都有同样的机会进入前 5。

12.3 熵

熵描述重复区碱基组成的复杂度。它只用 A、C、G、T 四个频率，取以 2 为底的对数。

H = − Σ px · log₂ px , x ∈ {A, C, G, T} H 的范围是 0 到 2。全部相同碱基时 H = 0。四种碱基等频时 H = 2。

以 TCATCGG（A:1、C:2、G:2、T:2，共 7 个）为例：

H = −[ (1/7)·log₂(1/7) + 3·(2/7)·log₂(2/7) ] ≈ 1.95 程序输出 1.95。低熵的重复（如 AAAAAA）更容易是低复杂度噪声。

13.2 冗余的定义

两条记录 i 与 j。先看区间重叠比例。i 的区间有 90% 以上被 j 覆盖时，才考虑删除 i。

再看周期关系，满足任一条就删除 i：

if i.period > j.period && i.period % j.period == 0
        && (i.score as f64) <= 1.1 * j.score as f64 {
    return true;                                  // i 是 j 的整数倍，且分数不占优
}
if i.period == j.period && i.score <= j.score {
    return true;                                  // 周期相同，分数更低
}

第一条规则的含义：若 i 的周期是 j 的整数倍，j 是更基本的描述。除非 i 的分数比 j 高出 10% 以上，否则删掉 i。

保留 i 的条件：i.period % j.period == 0 且 i.score > 1.1 × j.score 1.1 是容差。长周期能解释更多匹配，分数本来就偏高。没有容差会误删。

判据criteria决定候选是否进入 DP 的规则。
带状banded只计算对角线附近的格子。
回溯traceback从最大分处沿前驱走回起点，得到比对。
屏障barrier把 0 改写为 −1000，禁止路径通过。

17动手验证

17.1 构建并运行

cargo build --release
./target/release/trfrs tests/data/small_test.fasta 2 5 7 80 10 50 2000 -ngs

-ngs 模式把紧凑的 .dat 打到标准输出，不写文件。适合观察。

17.2 与参考答案比对

./target/release/trfrs tests/data/small_test.fasta 2 5 7 80 10 50 2000 -ngs \
  > /tmp/out.txt
diff /tmp/out.txt tests/data/small_test.fasta.out

没有输出就说明逐字节一致。这是移植版本最强的正确性证据。

17.3 建议的观察点

若要真正理解判据，建议做三个实验。每个实验只改一处，不要同时改。

  1. 改 Minscore。把 50 改成 1000，观察输出变少。这说明 Minscore 是最后一道门，不影响 DP 过程。
  2. 改 PM。从 80 改成 75，程序会自动切换成 4 种元组长度（3、4、5、7）。这两行信息写进明细文件（*.txt.html）开头附近，不在 stderr：找 tuple sizes 与 tuple distances。
  3. 加 -r。关掉冗余剔除，观察是否有被删掉的倍数周期。

17.4 用调试器看内部量

criteria_count[d] 记录每个周期通过判据的次数。cell_count[d] 记录 DP 算过的格子数。两者都只在内存里，不写文件。断点放在 process_candidate() 的出口，就能看到候选的完整一生。

18自查问题

下面的问题覆盖全书。先自己答，再展开对照。

1. 为什么扫描阶段要用三种长度的元组，而不是只用最长的那种？

长元组更特异，但覆盖的距离有限。距离 7 的重复在 7 元组看来只有少数几个匹配点，证据不足。短元组便宜，能覆盖短距离的全部位置。用三种，是按距离分工，兼顾成本与灵敏度。

2. 一个距离 d 为什么只由一种元组长度处理？

因为判断条件是 d 大于上一种元组的覆盖上限。同一种距离若被两种长度处理，DP 会重复跑，结果不变，成本翻倍。

3. nummatches 数的是元组个数还是碱基数？为什么？

是碱基数。新增条目时加 size（元组长度），合并相邻元组时加 1。这样阈值表可以直接按“证据覆盖了多少碱基”来定，与元组长度无关。

4. 为什么 DP 的列号要对 size 取模？

因为模式是循环使用的。取模后，同一张表可以同时容纳任意多次拷贝，而且不需要事先知道重复的相位。

5. 每行扫两遍会不会改变结果？

不会，但它也不是精确解。列号取模造成同行循环依赖，一次扫描解不开。第一遍给初值；第二遍除回绕处外都用同行已算出的值，回绕处用第一遍的值。这是定义良好的两步迭代，C 参考实现正是这样做的。

6. 屏障为什么用 −1000，而不用 −1？

−1 仍可能被 max 选中（当四个前驱都很差时）。−1000 比任何可能的真实分数都小一个数量级，所以它一定能输，等价于“此路不通”。

7. 为什么 bandwidth 用 d_range，而不用固定的 6？

因为漂移随周期增长。固定 6 在长周期下会让带跟丢，造成分数偏低。用 d_range 可以覆盖 95% 的相位漂移，同时带宽仍远小于周期。

8. 带状回溯里“合法的 0”是什么问题？

带边界会切断前驱，使 max 只能取 0。这个 0 不是真实终点。若不区分，回溯会提前停止，比对变短。程序检查三个前驱能否解释这个 0，能解释就继续走。

9. 为什么报告里的 period 可能不等于 size？

size 是共识模板的长度。period 是相邻拷贝在序列上的实际间距，由匹配位置距离的众数得到。有插入缺失时，两者会不同。

10. 为什么共识序列要用多数票，而不是直接取第一份拷贝？

第一份拷贝可能自己就带错配或缺失。多数票能把各份拷贝的噪声互相抵消，得到更接近“祖先拷贝”的模板。重对齐后分数更高，边界更准。

11. 一段 ACGT 完美重复，会不会同时报告周期 4、8、12？

可能进入 DP，但最终只会留下一个。第一，周期 8 的 k-run 阈值更严，可能过不了判据。第二，即使通过，冗余剔除会发现 8 是 4 的倍数且分数不占优，将其删除。

12. 为什么 Minscore 放在最后判断，而不是在扫描阶段？

扫描阶段还不知道分数。分数只能由 DP 算出。所以 Minscore 是最后一道门，它不节省 DP 的成本，只控制输出。

  1. 给 process_candidate() 加一行打印，观察 d、nummatches、maxscore。
